# mongo-backup

نظام نسخ احتياطي تلقائي لقاعدة بيانات MongoDB المُدارة (`49`) على DigitalOcean. يشغّل `mongodump` بشكل دوري، يرفع الأرشيف المضغوط إلى DigitalOcean Spaces عبر `rclone`، يولّد رابط تحميل مؤقت صالح 24 ساعة، ويرسل إشعار بريد إلكتروني (نجاح أو فشل) عبر Brevo. يعمل تحت إدارة PM2 باستخدام `cron_restart` بدلاً من cron التقليدي.

---

## التثبيت

```bash
pnpm install
cp .env.example .env
```

افتح `.env` وعبّئ القيم الحقيقية (خصوصاً `MONGO_URI`, `BREVO_API_KEY`, `MAIL_FROM`, `RCLONE_CONFIG`, `BACKUP_DIR`).

افتح [src/recipients.ts](src/recipients.ts) وضع بريد كل شخص تريد وصول الإشعارات إليه داخل المصفوفة:

```ts
export const recipients: string[] = ['ahmed@example.com', 'sara@example.com'];
```

هذا الملف كود عادي (مش `.env`) لأن قائمة المستلمين تتغيّر نادراً وتستفيد من مراجعة عبر git/PR مثل أي تعديل آخر في الكود.

> ⚠️ **مهم:** بما أن `recipients.ts` يُجمَّع داخل `dist/main.js` وقت البناء، أي تعديل عليه **لا يصبح فعّالاً إلا بعد** `pnpm build` (ثم `pnpm pm2:trigger` أو إعادة تشغيل PM2). خلافاً لـ `.env` الذي يُقرأ وقت التشغيل مباشرة.

```bash
pnpm build
```

هذا ينتج `dist/main.js` عبر tsup.

> ⚠️ هذا المشروع يُبنى على السيرفر (Ubuntu 24.04) لأن `mongodump` و `rclone` غير متاحين على أجهزة التطوير الشخصية عادةً. يمكنك تشغيل `pnpm typecheck` و `pnpm build` محلياً بأمان، لكن `pnpm start:prod` سيفشل محلياً بكود خروج `3` إن لم تكن الأداتان مثبّتتين — وهذا سلوك متوقّع.

## تجربة يدوية قبل الجدولة

على السيرفر، بعد `pnpm install && pnpm build`:

```bash
pnpm start:prod
echo "exit code: $?"
```

راجع المخرجات في الطرفية للتأكد من نجاح كل مرحلة (preflight → dump → upload → link → retention → notify → done). كود الخروج المتوقع عند النجاح هو `0`.

---

## التشغيل عبر PM2

```bash
pnpm pm2:start
pm2 save
pm2 startup        # نفّذ الأمر الذي يطبعه pm2 لتفعيل التشغيل عند إقلاع السيرفر
```

PM2 لا يبقي العملية تعمل باستمرار — `autorestart: false` مضبوط عمداً، والعملية تُعاد فقط حسب جدول `cron_restart` (`0 2,14 * * *` بتوقيت UTC، أي 5 صباحاً و5 مساءً بتوقيت القاهرة صيفاً — راجع قسم الجدولة أدناه).

## تشغيل فوري للاختبار

لتشغيل نسخة فورية دون انتظار الجدولة:

```bash
pnpm pm2:trigger
pnpm pm2:logs
```

## الاسترجاع

النسخ لا تُرفق بالإيميل (حجمها أكبر من حد Brevo)، بل تُحمَّل عبر الرابط المؤقت المُرسل أو مباشرة عبر rclone:

```bash
rclone copy dospace:qutuz-db-backups/mongo/<FILE> /tmp/
```

### استرجاع آمن إلى قاعدة اختبار منفصلة (موصى به)

```bash
mongorestore --uri="<URI>" --archive=/tmp/<FILE> --gzip \
  --nsFrom='49.*' --nsTo='49_restore_test.*'
```

هذا يستعيد البيانات إلى قاعدة جديدة `49_restore_test` دون المساس بقاعدة `49` الحالية.

### ⚠️ تحذير بخصوص `--drop`

لا تستخدم `mongorestore --drop` على قاعدة `49` مباشرة إلا إن كنت متأكداً تماماً من قرارك — هذا الخيار **يحذف** المجموعات (collections) الموجودة قبل استعادة البيانات فيها، وهو غير قابل للتراجع. اختبر الاسترجاع دائماً على `49_restore_test` أولاً.

## جدول المواعيد

| التوقيت (UTC) | القاهرة (صيفي، UTC+3) | القاهرة (شتوي، UTC+2) |
|---|---|---|
| 02:00 | 05:00 | 04:00 |
| 14:00 | 17:00 | 16:00 |

مصر لا تطبّق التوقيت الصيفي حالياً بشكل ثابت — تحقق من القرار الرسمي كل عام إن كان دقة الساعة مهمة لديك. جدولة PM2 (`cron_restart`) تعمل دائماً بتوقيت UTC بغض النظر عن `TZ_DISPLAY` (المستخدم فقط لعرض الوقت داخل نص الإيميل).

## حل المشاكل الشائعة

**فشل الاتصال بقاعدة البيانات (`MongoNetworkError` أو مهلة اتصال)**
- تأكد أن عنوان IP الخاص بالسيرفر مضاف إلى "Trusted Sources" في إعدادات الـ cluster على DigitalOcean.
- تحقق من صحة `MONGO_URI` (خصوصاً كلمة السر وعدم انتهاء صلاحيتها).

**فشل الرفع إلى Spaces**
- تحقق من صلاحية مفاتيح Spaces (Access Key / Secret) المُعدّة داخل `rclone.conf` — قد تكون منتهية أو مُلغاة.
- جرّب يدوياً: `rclone lsd dospace:` للتأكد من أن الاتصال بالـ remote يعمل أصلاً.

**قفل يتيم (`.lock` عالق)**
- إن توقفت العملية بشكل غير طبيعي (قطع كهرباء، `kill -9`) قد يبقى ملف `<BACKUP_DIR>/.lock` موجوداً. النظام يتحقق تلقائياً من كون الـ PID المُخزّن في الملف لا يزال حياً؛ إن كان ميتاً يتجاهل القفل ويكمل التشغيل تلقائياً — لا حاجة لتدخل يدوي عادةً. إن أردت التأكد يدوياً: `cat <BACKUP_DIR>/.lock` ثم `ps -p <PID>`.

**لم يصل إيميل الإشعار**
- راجع `pnpm pm2:logs` بحثاً عن رسائل `[notify]` — فشل Brevo لا يوقف الباك أب لكنه يُسجَّل كتحذير.
- تحقق من أن `BREVO_API_KEY` صالح وأن `MAIL_FROM` مُتحقق منه (verified sender) في حساب Brevo.

## إضافة التشفير لاحقاً

النسخ الحالية غير مشفّرة. لإضافة تشفير دون تعديل أي كود، أنشئ remote جديد من نوع `crypt` يغلّف الـ remote الحالي:

```bash
rclone config
# اختر: n) New remote
# الاسم: dospace-crypt
# النوع: crypt
# remote: dospace:qutuz-db-backups/mongo
# filename encryption: standard
# عيّن كلمة سر قوية عند الطلب واحفظها في مكان آمن (مدير كلمات سر)
```

ثم في `.env` غيّر:

```dotenv
REMOTE="dospace-crypt:"
```

### ⚠️ تنبيه مهم

**التشفير يُعطّل فائدة رابط التحميل المؤقت.** الرابط الذي يولّده `rclone link` يشير إلى الملف كما هو مخزَّن فعلياً على Spaces — وإن كان مشفّراً، فإن تحميله عبر الرابط مباشرة (متصفح أو `curl`) يُنتج ملفاً مشفّراً غير قابل للاستخدام دون rclone وكلمة السر لفكّه. بعد تفعيل التشفير، الاسترجاع يتطلب دائماً المرور عبر `rclone copy` (باستخدام remote الـ crypt) بدلاً من رابط التحميل المباشر.
